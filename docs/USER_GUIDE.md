# 用户使用手册

## 1. 登录

浏览器打开 `http://<服务器>:8080`，使用管理员账号登录（默认 `admin / admin123`）。

## 2. 创建项目

右上角「+ 项目」输入名称创建。项目是数据隔离单位，所有资产、任务、漏洞均归属项目。

## 3. 导入资产

进入「资产导入」页面，粘贴授权目标，支持：

```
192.168.1.1              # 单 IP
192.168.1.0/24           # CIDR（超过 /12 的范围会被拒绝）
192.168.1.10-192.168.1.20 # IP 段
example.com              # 域名
https://app.example.com  # URL
```

系统自动去重并区分公网/内网。

## 4. 创建扫描任务

进入「扫描任务」→「+ 创建扫描任务」：

- **快速模式**：空间测绘 + 常见端口扫描（最快）
- **标准模式**：空间测绘 + Top1000 端口扫描 + 漏洞扫描（敏感路径检测 + 规则库）+ 弱点检测（链接爬取与 WIH JS 敏感信息）
- **深度模式**：空间测绘 + 全端口扫描（1-65535）+ 全部漏洞扫描 + URL/API 发现（最慢）

三种模式均执行空间测绘与端口扫描；任务中显式指定端口时覆盖模式默认端口集。

可配置端口（空=常用端口 / `80,443` / `1-1000` / `full` 全端口）、并发数、超时、优先级，以及
**扫描周期**（一次性 / 每 8 小时 / 每 24 小时 / 每周）——设置周期后任务成为资产监控任务，
到期自动重新执行，每次新增的资产/端口/Web/漏洞自动进入「变化监控」。

任务运行中可**暂停 / 恢复 / 终止**，可查看实时日志。已完成 / 已终止 / 失败的任务支持**编辑**
（修改名称、目标、模式、端口、并发、超时、周期后保存）与**重启**（按当前参数重新执行）；运行中 /
排队中 / 暂停中的任务不可编辑，需先终止或等待结束。

## 5. 查看资产

「资产管理」包含五个视图：

- 支持**导出 CSV / JSON**（按当前视图类型导出对应资产）。
- **IP**：存活状态、探测方式、风险评分。点击任意 IP 打开**资产画像**，查看其关联的域名、开放端口/服务（含自动分类）、Web 资产与技术栈、关联漏洞。
- **域名 / 端口 / Web / URL**：对应资产列表，支持搜索。

## 6. 漏洞风险

「漏洞风险」页按等级（Critical/High/Medium/Low/Info）过滤查看，包含漏洞名称、影响资产、端口、URL、组件、修复建议；可一键导出 CSV / JSON。

## 5.1 资产白名单

「系统设置 → 资产白名单」配置不做漏洞扫描的资产（每行一项）：精确 IP、CIDR 网段、域名
（自动覆盖子域名，支持 `*.corp.cn` 写法）。白名单内的资产在扫描任务与 POC 监控触发的全资产
扫描中都会**跳过漏洞与弱点检测动作**（敏感路径检测、规则引擎、链接爬取与 WIH），但资产发现、端口扫描、Web 识别照常执行。

任务列表与资产管理页均支持**删除**：任务删除（运行中先终止，连带日志）、五类资产的删除。

## 6.1 漏洞规则库（PoC 检测）

「漏洞规则库」页支持导入 nuclei / xray / afrog 三种 YAML PoC，导入方式：

1. **POC 文件仓库**：把 POC 放入 `data/poc` 对应类型目录（页面可上传，自动归类），进入目录点「导入当前目录到规则库」
2. **模板源更新**：配置 GitHub 模板仓库源后「立即更新」，自动 clone/pull 并导入
3. **API**：`POST /api/vuln-rules/import {"path":"服务器目录"}` 仍可用于批量导入
2. 用来源/等级/启用/可执行筛选与搜索管理规则；每条可「测试」（对指定 URL 单规则试探）、
   查看 YAML 原文、停用、删除
3. 深度扫描任务默认对每个 Web 资产执行**全部**启用的可执行规则（「规则执行设置」中默认开启，
   每目标最大规则数 0 = 加载全部；如需控制耗时可改为具体条数），
   命中的 PoC 直接进入漏洞列表（组件列标注规则来源）

说明：部分规则使用引擎暂不支持的表达式（复杂 CEL/DSL 函数、search 回填、raw 请求等），
此类规则入库但标记「不可执行」，不会在扫描中运行。规则发起的均为 HTTP 请求，请确保仅对授权资产启用。

**POC 文件仓库**：`data/poc` 目录是平台统一存放 PoC 文件的仓库，页面上可分级浏览（面包屑导航）、
新建文件夹（支持一次创建多级，如 `web/rce`）、上传 .yml/.yaml 文件（上传前自动校验规则格式）、
**上传文件夹**（一次选择整个本地目录，即上传其中的所有 POC 文件：忽略所选文件夹本身的名字、
保留其内部子目录结构，自动过滤非 yaml 文件，文件按格式自动归入 xray/nuclei/afrog 类型目录，
如所选 `my-pocs/web/a.yaml` 落位 `nuclei/web/a.yaml`）、删除文件/目录、以及把当前目录一键导入规则库。
也可直接把 PoC 文件手工拷贝到 `data/poc` 子目录后在页面导入。

**POC 目录监控**：启用后（默认开启，默认每 60 秒检查一次，可在界面调整）自动监视 `data/poc` 目录——
发现新增或变更的规则文件即自动导入规则库，并立即用这些新规则对**勾选了漏洞扫描的项目**的全部 Web 资产
补扫一轮（项目下没有任何勾选漏洞扫描的任务则跳过该项目），检出的漏洞直接入库（来源标注 POC 监控）并写入变化监控。把新 PoC 文件丢进 `data/poc` 对应类型
目录即可自动生效，无需任何手动操作。

**模板源在线更新**：支持配置 GitHub 模板仓库源（默认为空，自行添加），「立即更新」会
clone --depth 1（已存在则 fetch + 重置到远端最新）并自动导入规则库；「每日自动更新」开关与**更新时间**（默认 02:00，可改）即时保存，每日到点自动拉取；更新时会与库中已有规则对比，
**仅对本次新增的 POC 按项目漏洞扫描意图触发补扫**（仅勾选了漏洞扫描的项目，更新的旧规则不重复触发）；克隆默认存放在 **POC 仓库的 nuclei 类型目录**
（`data/poc/nuclei/owner/repo`，可在文件仓库页面浏览），更新期间自动暂停 POC 目录监控避免误触发全资产扫描；GitHub 直连失败时自动加镜像前缀重试
（默认 `https://ghproxy.com/`，可在界面改为其他可用镜像）；可开启每日自动更新。源列表顺序即优先级，
不同仓库的重复模板保留先到（官方库建议放最前）。

**WIH JS 敏感信息检测**：弱点管理页内置 WIH 卡片（Web Info Hunter，默认规则集移植自 [WIHscan](https://github.com/ifacker/WIHscan) / MIT），
对站点首页与引用 JS（默认每站最多 20 个，可调）做正则敏感信息匹配：云 AK/SK（阿里云/腾讯云/Grafana）、
JWT、疑似密码、企业微信/钉钉/飞书/Slack 机器人 Webhook、身份证号等。命中归入**弱点管理**（类型 WIH JS），
凭据类判为高危。规则支持启停、编辑正则、新增与删除；「即时检测」输入任意页面或 JS 的 URL 可单目标试跑
（对应 WIHscan 的 -u 模式）。「扫描时执行」为总开关，实际执行随任务的**弱点检测**阶段（未勾选弱点检测的任务不执行），保存后即时生效。

## 6.2 资产监控

「资产监控」页集中管理所有配置了扫描周期的任务：显示周期、当前状态、上次结束时间与下次执行时间，
支持「立即执行」「暂停 / 恢复 / 终止」。调度器每分钟检查一次，任务结束时间 + 周期到期后自动重新排队
（到点误差为分钟级）；上次执行失败的周期任务到期后也会自动重试；进程重启时，上次被中断的任务自动恢复排队继续执行。

**证书透明度收集**：「资产导入」页输入根域名即时查询 CT 日志中的历史子域（crt.name 主源、crt.sh 备用，
出站走全局代理），勾选后一键导入为项目域名资产，进入后续扫描链路；扫描任务内的子域名枚举同样使用双源 CT 被动收集。

**新增 Web 资产自动扫描**（按来源分两条路径）：**任务发现**的 Web 在任务内即时判定——项目下存在勾选漏洞扫描的任务才触发漏洞扫描，勾选弱点检测的任务执行弱点与 WIH 检测，两者都不勾选则仅入库不检测；**资产导入的 URL / 空间测绘导入**的 Web 由实时扫描器异步补扫（标准模式语义：敏感路径 + 规则库 + 弱点 + WIH；白名单资产仍跳过，通常数秒内完成），可在配置 `scan.web_autoscan` 关闭。

## 6.3 弱点管理（暗链 / 坏链 / 敏感字 / WIH）

「弱点管理」页集中展示弱点检测阶段（任务勾选"弱点检测"才执行）的检出结果：暗链（隐藏链接 + 目标页内容核验）、
坏链（四层误报控制）、敏感字、WIH JS 敏感信息；支持类型筛选、标记（实报/误报）、单条与批量 AI 研判。

**弱点检测设置卡**：总开关（链接爬取/暗链/坏链/敏感字/WIH JS）、暗链目标内容核验开关、每站点最大爬取页面数/检查链接数、
**统一词库·手动部分**（敏感字与暗链关键词共用，每行一个）、坏链忽略域名。生效规则：
敏感字 = 手动词库 + 订阅词表；暗链关键词 = 历史暗链词 ∪ 手动词库 + 订阅中勾选"暗"的文件词表
（手动词库两用；订阅的内容审核类词库默认不参与暗链匹配——外链锚文本命中政治类词会大量误报，需要时在文件上勾选"暗"启用）。

**敏感字词库订阅**：设置卡下方可订阅任意 GitHub 敏感词仓库或自定义 raw 源（默认预设 [konsheng/Sensitive-lexicon](https://github.com/konsheng/Sensitive-lexicon)，MIT，可一键恢复）——

- **订阅源自定义**：订阅源支持 `github.com` 仓库页（自动转 raw 基址，支持指定分支）、`raw.githubusercontent.com` 基址或任意自定义 http(s) raw 源；「发现文件」自动拉取 GitHub 仓库内的 .txt 清单（过滤 .github 等元数据）供勾选，「＋ 文件」手工添加路径，文件条目可勾选/移除，不再绑定特定仓库
- 默认预设勾选：政治/反动/暴恐/色情/贪腐/民生/涉枪涉爆/广告等分类词库与网易前端过滤通用大词库，
  零时-Tencent（超大）、非法网址（URL 清单）、GFW 补充默认关闭，可自行开启
- 「立即更新」即时拉取（UTF-8/GBK 编码自动归一、注释与 URL 行过滤、去重、总量上限 6 万词）；
  拉取为**直连**（订阅属平台自身出站，不走全局代理，与空间测绘同约定），
  GitHub 直连失败自动用镜像前缀重试（默认 ghproxy.com，可改或留空禁用）
- 「每日自动更新」到设定时刻（默认 02:00）自动拉取，当日只尝试一次（失败次日重试）
- 订阅词与手动词库**合并生效**参与页面敏感字检测；更新记录各文件词条数与失败明细
- **词库管理**：更新入库后「管理词库」弹窗提供词条管理——**词条**页签：分页浏览/搜索（每页 100 条）、
  来源标识（拉取/手工）、手工**新增**词条（空格/逗号/换行分隔批量，订阅更新后保留，暗链/敏感字两用）、**删除**词条
  （单条或勾选批量，删除记入排除清单，订阅更新不会拉回）；**排除清单**页签：查看被删词条（支持搜索）、
  单条或全部**恢复**（立即回到生效词表）。弹窗头部实时统计生效/拉取/手工/排除四类词量，
  生效词表 = 拉取 + 手工 − 排除。订阅文件条目旁的「暗」勾选控制该文件词表是否同时用作暗链关键词。

## 7. 变化监控

「变化监控」记录每次扫描新增的 IP、端口、Web、URL、漏洞——再次扫描同一目标后，新增项会自动出现在这里。

## 8. 报告导出

- 漏洞页支持 CSV / JSON 导出；
- API `GET /api/export?type=...&format=csv|json` 支持全部资产类型导出；
- `GET /api/reports` 返回含统计、高风险资产 Top、漏洞详情的汇总 JSON，可直接用于报告生成。

## 9. 角色权限

- **admin**：全部功能
- **auditor**：查看 + 任务控制 + 资产导入
- **viewer**：仅查看

## 10. 安全与合规

- 仅对已授权目标发起扫描；
- 全部检测为非破坏性（GET 请求 / Banner / TLS 握手）；
- 所有登录与关键操作均记录审计日志（`GET /api/system/logs`）。
